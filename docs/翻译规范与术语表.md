# 《Refactoring UI》中译规范与术语表

本书是 Adam Wathan 与 Steve Schoger 写给**开发者**的界面设计实战书。翻译要服务的中文读者
和原文读者完全一致：会写代码、想让自己做出来的界面变好看，但没有设计背景。

---

## 一、硬性格式规则（违反即为失败）

1. **结构必须逐段对应。** 英文有 N 个段落，中文就有 N 个段落。不得合并、拆分段落，不得增删。
2. **列表项数量必须一致。** 英文 5 个 `- ` 条目，中文就是 5 个 `- ` 条目。
3. **以下内容一字不改，原样保留：**
   - 图片引用：`![](assets/p123-01.png)`
   - 页码锚点注释：`<!-- p123 -->`（包括句尾的行内形式 `... <!-- p124 -->`）
   - 代码、CSS 属性、颜色值（`#RRGGBB`、`hsl(...)`）、字体名、`h1`/`h2` 这类标签
4. **标题层级不变。** `#` 还是 `#`，`##` 还是 `##`，`###` 还是 `###`。标题只写中文，不要附加英文原文。
5. **粗体 `**...**` 和斜体 `*...*` 的位置要落在语义对应的中文词句上**，不要照搬英文的边界。
6. 输出文件必须是 **UTF-8 无 BOM**。

## 二、语言风格

- 人称：一律用「你」，绝对不用「您」。
- 语气：直接、务实、带一点作者的幽默感。原文很多句子很短、很干脆（"Start with that."），
  **不要**为了"通顺"把它们抻成长句。短句是这本书的风格，请保留。
- 不要翻译腔。具体自查项：
  - 少用被动式（"被"），能改成主动就改。
  - 不要连续出现三个以上的「的」。
  - 不要出现「一个」「一种」这种在中文里冗余的量词（"a feature" 就是「功能」，不是「一个功能」）。
- 术语表里的词，全书统一，不换同义词。
- 中英文之间、中文与数字之间加一个半角空格（例：用 Tailwind CSS 构建、3 个像素）。
- 标点用中文全角：，。：；？！（）「」改为 **“ ”**。破折号用 ——。
  引号统一用弯引号 “ ”，单引号用 ‘ ’。括号内是英文短语时用半角 ()。
- 句末不要保留英文句号。

## 三、不翻译的内容

- **界面示例文案**：按钮文字、导航项、表单标签等英文示例（如 "Save changes"、"Sign up"）
  **保留英文原样**，不要加中文注释。书中讨论的就是英文界面。
- 人名、产品名、品牌名、字体名、公司名：Adam Wathan、Steve Schoger、Jason Fried、Tailwind CSS、
  Basecamp、Google、Unsplash、Mailchimp、Sketch、Figma、Inter、Helvetica、Graphik 等，全部保留英文。
- 网址、文件名。

## 六、交付前自检

写完文件后必须运行检查，并把结果写进你的最终汇报：

```powershell
python -c "import pathlib,re,sys; p=pathlib.Path(r'<你写的文件>'); t=p.read_text(encoding='utf-8'); print('headings', {n: len(re.findall(r'(?m)^#{%d} ' % n, t)) for n in (1,2,3)}); print('images', t.count('![](assets/'), 'anchors', len(re.findall(r'<!-- p\d+ -->', t)))"
```

把输出和对应英文源文件的数字对比，必须一致。另外通读一遍中文，确认没有漏译整段、没有残留
未翻译的英文句子（界面示例、专有名词除外）。

## 七、汇报里必须包含

- 你负责的章节文件和路径
- 结构自检的数字（标题数、图片数、锚点数）
- **你新造的术语译法**（不在上表里、但你判断全书需要统一的词），格式：`english → 中文`
